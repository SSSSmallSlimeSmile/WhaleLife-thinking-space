# 思维画布（子插件）

思维空间拆出来的画布：一张单文件网页 + 一个本地小服务。它现在是**子插件** `thinking-space/canvas`，
随父插件一起装、一起启用，自己管启停和端口。

主说明见 [../../README.md](../../README.md)，这里只讲画布这一层。

使用手册：[docs/使用-思维画布.md](../../docs/使用-思维画布.md)。

## 两份文件

```
index.html                 画布页面本身，单文件，样式和脚本都内联
whalelife-workbench.cjs    本地服务，默认监听 9281
```

## 跑起来

```
1  装好并启动 WhaleLife 宿主（画布靠它取插件列表、市场目录、工具目录）
2  打开宿主 → 插件页面 →「思维画布」（父插件「思维空间」卡片下的子插件）
3  点「启动画布」，等端口起来
4  浏览器打开 http://127.0.0.1:9281/
```

停止：同一页点「停止」。宿主端口连不上两次，画布会自己退。

端口和脚本路径都在这页的设置里。**上游端口不用填**：画布自己读宿主 `config/config.json` 的 `web.port`，
读不到就不启动——宁可不起，也别连到别的实例上去。

## 只停自己启动的

同一台机器上常常开着两个 WhaleLife（日常一个、干净实例一个），端口又都默认 9281。

所以启停加了归属判定：

- 这个实例拉起画布时带一个自己的标识（`--owner <id>`，存在插件 `data/config.json` 里，重载后还在）
- **启动**：端口已被占用、而归属标识对不上时，不接管，只报端口、PID 和「不是这个实例启动的」
- **停止**：归属对不上就不动它；脚本名相同不算数（两个实例跑的是同一个 `whalelife-workbench.cjs`）
- **宿主退出**：先拿进程句柄直接结束（这个句柄是插件自己 spawn 出来的，句柄没关之前系统不会复用这个 PID），
  句柄不在了才退回到「只杀核对过归属的那个 PID」

**对外只说端口、PID 和拒绝原因，不转述进程参数。** 命令行里可能带着别人的路径和资料，
而设置页的跳转地址和工具结果都是能被复制走的。归属判断仍然读命令行，但那一步只在插件内部发生。

标识只在插件自己的配置里，不影响命令行手工启动的用法——手工起的不带 `--owner`，插件不会去停它。

## 跟着思维空间走

设置页那个「思维空间停掉时，画布一起收掉」默认勾着：停用父插件 → 宿主先停子插件 → 画布进程一起收。
不勾就各停各的，画布会挂到宿主退出或你手动停。

**重载父插件也会收掉画布**（重载 = 停用 + 启用），要接着用就再点一次启动。

宿主给插件收尾的预算只有 1 秒，超时直接 SIGKILL 子插件，清理函数里剩下的话一句都跑不到。
所以收尾这一段只做快事，一次进程查询都不做——以前在这里用 PowerShell 查命令行，光查一次就要
0.4–0.6 秒，机器一忙就超时，画布就成了孤儿、端口一直占着。

另外画布自己也有兜底：插件拉起它时带 `--parent-pid <宿主进程号>`，每 2 秒看一眼宿主还在不在，
宿主被硬杀、插件来不及收尾时自己退出（实测 2 秒内）。手动跑脚本不带这个参数就没有这层看护。

## 用命令行直接跑

```bash
node whalelife-workbench.cjs --port 9281 --upstream 9272
```

- `--port`：画布监听的端口，默认 9281
- `--upstream`：宿主端口，默认 9270

两个端口也可以走环境变量：`WORKBENCH_PORT` / `WORKBENCH_WHALE_PORT`。命令行参数优先，其次是环境变量，都没有才用默认值。两个端口不能相同。

设置环境变量 `WORKBENCH_WATCH_PARENT=0` 可以关掉"宿主退出就自己退"的看门狗；`WORKBENCH_WATCH_GRACE_MS` 改启动缓冲，默认 15000 毫秒。

## URL 参数

| 参数 | 作用 |
|---|---|
| `?flow=<流程id>` | 打开后居中到这条流程 |
| `?node=<节点id>` | 顺便选中某个节点（可以和 flow 一起用） |
| `?skill=<技能id>` | 从技能库取一条技能，注入成节点并选中 |

`?skill=` 需要宿主在跑，且父插件里注册了 `GET /plugins/thinking-space/skill?id=` 这条路由。

## 依赖

- WhaleLife 宿主在跑
- 需要宿主的同源代理能到 `/plugins/thinking-space/*` 和 `/market/*`
- 启停走 `taskkill` / PowerShell，**只在 Windows 验过**；Linux 和 macOS 上按钮会失败，需要手动 `node whalelife-workbench.cjs`

## 状态

实验性。页面在浏览器里跑通过，但**不是每项功能都在真实环境逐条验证过**。和技能库的同步是**单向为主**：画布上的流程点「发布到思维空间」会转成技能写进 `skills.json`（跨步骤连线要填字段路径，如 `data.text`），技能库那边列在「技能组」标签里只读对照；反过来，技能不会自动变成画布上的流程。

契约问题（端口声明、双向同步）见 [../../docs/插件接入规范.md](../../docs/插件接入规范.md)。
