# 思维空间（thinking-space）插件说明

一个让 WhaleLife 能「把一串工具调用存成技能」的插件。

不是画布。画布是前端，这是后端和读写接口；画布上的节点最终要落到这份技能定义上，才有办法真跑。

- 包：`WhaleLife-thinking-space-20261120.zip`（8 个文件，49 KB）
- 版本：0.1.0
- 依赖：`web`、`tools`
- 本机跑在 WhaleLife `2ee7b09` 之后的自建分支上

---

## 一、为什么做这个

现在每次调用工具，都要模型先推理「该调哪个、参数填什么」，再等一轮结果，然后在下一轮把整段上下文重新发一遍。搜个资料读正文，是三轮对话。

如果这串动作是固定的（「搜索 → 读第一条 → 汇总」这种），第二、三次就不该再让模型重新想一遍。

技能库要解决的就是这一件事：**把动作序列固化下来，一次调用跑完，中间不经过模型推理。**

实测数据（在 `personal-test/思维空间/实测数据-20261120.md`，这里是摘要）：

| | 原生调用 | 技能组 |
|---|---|---|
| 对话轮数 | 3 | 2 |
| input token | 71,269 | 48,127（−32%） |
| 墙钟时间 | 99.6 秒 | 17.7 秒（−82%） |
| 中间步骤是否需要模型思考 | 每步一轮完整推理 | 不需要，按链直走 |

**反面同样重要**：同一次测试里我第一次把参数名写成 `query`（技能声明的是中文名），多废一轮，实际用了 94,714 token——比原生还多 33%。**技能组的省钱有个前提：参数得对。** 错一次，省下的全赔进去，而且链越长赔偿越大。

## 二、设计上的三个选择

### 1. 状态放服务端，不放浏览器

画布原型的工程存在 `localStorage`，模型读不到、改不了，只能当展示品。技能库把定义放在 `data/skills.json`，工具和页面读同一份。

这样模型能自己写技能、能改、能跑，人能看、能编辑、能导出。两边是同一个真源。

### 2. 技能是数据，不是代码

一条技能就是一段 JSON：参数声明、步骤数组、每步的工具名和参数、`next` 链。没有条件分支、没有循环、没有表达式。

**限制是有意的。** 技能要被自动生成（从调用记录里学）、被自动改写（跑熟了精简）、被用户手动编辑、被跨机器导入导出——如果它是代码，这四件事都会变成「审代码」，风险大得多。

代价也很实在：需要临场判断的活（「第一条读不了换第二条」这种）只能靠 `$try` 把候选写死，不能靠脑子现想。

### 3. 执行权和意图分开

含写到磁盘、跑命令、发消息、出声这类步骤的技能，跑之前要求 `confirmSideEffects: true`，否则直接 `blocked`。**存下来不等于能跑。**

自动整理同理：它默认不整理含确认步骤的链，就算打开了开关，跑的时候到那一步还是会被拦。整理器不放大执行权。

## 三、工具与页面

### 六个工具

```
space_skills()                            列技能（含 runs / lastStatus / rev / hints）
space_skill_save({ id, spec })            新建或覆盖，校验不过返回 blocked + 原因
space_draft({ name, tools })              工具名 → 草稿（查归属、声明参数、连链、预校验）
space_run({ id, params, confirmSideEffects })   真跑，返回逐步回执
space_trace({ runId, recent })            按 runId 取回运行记录（内存留一小时）
space_organize({ force })                 从调用记录里整理技能
```

`space_draft` 是这几个里最实用的：手写 spec 容易在 `${n1.data.results[0].url}` 这种地方栽，草稿把骨架生成好，人只改参数引用。

### 八条路由

```
GET  /plugins/thinking-space/          介绍 + 状态 + 设置 + 打开画布
GET  /plugins/thinking-space/space     功能库 / 复合功能库列表
GET  /plugins/thinking-space/edit      步骤编辑（参数 JSON、上移下移删除、新增）
POST /plugins/thinking-space/edit      保存编辑
POST /plugins/thinking-space/run       页面上跑一次
POST /plugins/thinking-space/organize  立即整理
GET  /plugins/thinking-space/export    导出全部技能（下载 JSON）
POST /plugins/thinking-space/import    导入（合并：同 ID 覆盖，新 ID 新增）
```

**踩过的坑记一下**：宿主的 `ctx.web.page()` 只注册 GET，`ctx.web.api()` 只注册 POST。一开始把表单保存写在 `page()` 里，还加了 `if (req.method === "POST")` 判断——那个分支永远走不到，POST 直接 404，页面显示「接口不存在」。这两者要分开注册。

## 四、技能定义格式

```json
{
  "schemaVersion": 1,
  "name": "搜资料",
  "kind": "composite",
  "description": "搜索并读取首条可读网页",
  "params": [{ "name": "query", "label": "关键词", "type": "string",
               "required": true, "aliases": ["关键词", "q"] }],
  "steps": [
    { "id": "n1", "tool": "surf_search", "plugin": "surf",
      "params": { "query": "${query}", "limit": 3 }, "next": "n2" },
    { "id": "n2", "tool": "surf_read", "plugin": "surf",
      "params": { "url": { "$try": ["${n1.data.results[0].url}",
                                    "${n1.data.results[1].url}",
                                    "${n1.data.results[2].url}"] } },
      "next": null }
  ]
}
```

三件事值得说：

**参数名用工具 schema 的机器名，中文放 `label`。** 我用过「关键词」当参数名，结果调用时和 `surf_search` 的 `query` 对不上。现在 `query` 是机器名、`label` 是给人看的、`aliases` 收旧写法，三套并存但只有一个真名。

**占位符数组下标要方括号。** `${n1.data.results[0].url}` 对；写成 `.0.` 会被校验器拦下并指出是哪一步、该写成什么样。

**`{"$try": [...]}` 是候选回落。** 按顺序试，第一个成功就采用，每个候选的成败都进回执。今天实测：三个候选全废（豆瓣 `unsupported_content`、两条百度百科 `access_blocked`）时整步 `failed`，总耗时 5 秒多——**换候选不是免费的**。

## 五、执行器

### 五态

| 状态 | 含义 | 建议动作 |
|---|---|---|
| `ok` | 正常 | — |
| `failed` | 可重试 | 看 error |
| `uncertain` | 结果未知（单步超时） | **不要自动重试**，可能已有副作用 |
| `blocked` | 缺前置条件 | 补条件 |
| `skipped` | 这步没成但不影响后面，已继续 | 看整体 |

`uncertain` 是认真做的，不是为了凑数：出图、写文件这类超时时，图可能已经出了，重跑就多一张。所以超时**不重试、不判失败、不断言成功**。

单步超时（默认 60 秒）只是不再等，不中断底层调用。跟 `loop_guard` 的处理一致——强行中断比放弃等待更贵。

**全部步骤都是 `skipped` 时，整体抬成 `failed`。** 这是在实测中发现并改的：两步都跳过、一步没干成，原来报 `skipped`，看起来像没事。

### 业务失败识别

这是实际战场上撞出来的：`comfy_status` 发现服务没起时，返回的是提示文字而不是错误，`ok: true` 一路传下去，整条链以为成功了。

现在会看输出里的文字分两档：

```
强词（≤300 字内任意位置）  没在跑 / 未启动 / 已停止 / 显存不够 / 低于阈值 / 请先启动 …
弱词（仅 ≤60 字短句）      失败 / 错误 / 无法 / 找不到 / 拒绝 / error / failed / denied
```

长正文不参与弱词判定——`surf_read` 读回几千字网页，里面出现「错误处理」「失败重试」不能把它判成失败。**宁可漏判让模型自己判断，也不错杀。**

单测 8/8：正常返回、服务没起、显存不足、短句失败、长正文不误判、结构化结果、空对象、null。

## 六、自动整理：从调用记录里学技能

开着时监听 `tool/called`，记录工具名和成败。

```
排除      space_*（自己，防自我强化）、hands_*（动手类，永远会被跳过）
transient 标记的调用  只记名字和时间，不记参数和结果
```

算法：按会话分组 → 按时间排序 → 间隔超窗口就断开 → 切 2~5 步 n-gram → 出现次数 ≥ 阈值 → 库里没有同样序列 → 存成 `auto-<hash>`。

### 三条去重规则，都是踩出来的

**周期折叠**：`a,b,a`、`a,b,a,b` 这种能由 `a,b` 重复拼出来的，丢掉长的。第一版没做，连做三轮同一组合，技能库里就多出 2 步、3 步、4 步三个版本——跑 4 步那条等于把 2 步的事情做两遍半。

**错位周期**：判定要检查所有偏移量。原来的对齐从下标 0 开始，`[surf, ledger, surf]` 和 `[ledger, surf]` 认不出是同一个循环，结果存了一条三步的废链。

**反向折叠**：链里没有 `hands_` 这类顺序敏感工具时，`a→b` 和 `b→a` 等价，只留一条。`hands_write → hands_run`（先写文件再跑命令）和反过来不是一回事，不能折。

### 关于 `transient`

这一条值得单独讲，因为它是接口约定的一个意外后果。

`surf` 的作者把 `surf_search` / `surf_read` 标成 `transientResult: true`（意思是结果不进历史）。宿主发事件时带 `transient: true`，我的监听器第一行 `if (payload.transient) return`，于是**所有读取类工具都看不见**。

结果就是：自动整理能学到的只有「动手类」（危险，跳过）和「状态类」（没什么用），永远学不到真正有用的读取链。

现在改成：transient 的调用只记 `name / ts / ok / session`，**不记参数、不记结果**。工具名本身不含内容，防的是正文进历史，不是防名字被记录。

**如果作者有更明确的约定**（比如「transient 不得用于任何统计」），这条要改回来。

## 七、自动精简：跑熟了会变短

你觉得「熟练」该怎么体现？我的答案是**跑完一次就回头看：这条链有没有哪一步白跑。**

删步骤（四条全满足）：这步跑成了 · 输出没被后面任何一步引用 · 不是最后一步 · 工具不需要确认。

有副作用的步骤永远不自动删。**删到剩 2 步就停手**（复合技能最少 2 步），所以 4 步的链是逐步变短的：跑一次 4→3，再跑 3→2。第一版想一次砍到底，把 3 步砍成 1 步，校验器拒绝，异常被 catch 吞掉——表面看什么都没发生。现在 catch 也写一行日志。

砍候选：连续 3 次都是 `$try` 第一条命中，就砍掉后面从没命中的，清计数不反复触发。

每次改写版本号 +1，回执带 `trimmed: { from, to, dropped, revision, cut }`。

## 八、版本（revision）

保存时递增，运行结束比对。运行期间被改过就在回执里标出来：

> 这条技能在运行期间被改过（现在 rev 2，这次跑的是 rev 1 的定义）。

造这个场景的方法：让一个 15 秒的抓屏技能跑起来，第 900 ms 时改定义。

**没有做的是**：按 revision 冻结定义、运行结束后决定用新的还是旧的。现在只是告知。

## 九、和画布原型的关系

画布（`9281` 那个 393 KB 的页面）现在是独立的东西，状态在浏览器里。它跟这个插件通过两条线连：

```
「打开思维空间」按钮   设置项 spaceUrl，默认 http://127.0.0.1:9281/
导出 JSON             画布上的技能定义格式和这里一致，人工搬
```

**还没接的是双向同步**：画布上画的流程不能直接存进技能库，技能库里的技能也不能在画布上打开。要接得先给插件加工程读写接口（`GET/POST /projects`、`GET /state`），这需要先定契约。

## 十、需要上游支持的地方

按重要程度：

**1. 导航组声明。** 现在「管理」组那个入口是模型改 `core/ui/index.html` 和 `app.js` 硬加的。如果能在 `plugin.yaml` 里声明 `navigationGroup: "manage"`，这行就能删掉。

**2. 管理页列表里那一行去不掉。** 宿主会列出所有已装插件，插件自己没法隐藏。设置按钮也只能跳插件自己的页。

**3. 调用历史。** 插件启动前的 `tool/called` 看不到，重启归零。想补历史得另读会话记录。

**4. 业务失败约定。** 插件工具返回 `ok: true` 但正文写「服务没起」，这是普遍现象还是个例？如果上游能定一条约定（比如失败时返回 `ok: false`），我这层的文字嗅探就可以删掉。

**5. 能不能真正取消一个工具调用。** 现在超时只是不等，底层还在跑。

**6. `transient` 的边界**（见第六节）。

## 十一、没验过的

写在这里，免得让人以为都验了：

```
一  页面视觉        只确认 HTML 里元素在，没在浏览器看过排版
二  自动整理长期效果  今天存的多数来自调试操作，没在真实使用里跑够样本
三  长链收益         5 步链跑过三次（2.4–3.4 秒），但没有和原生对照，省多少不知道
四  并发             两条技能同时跑没测过
五  uncertain        只真撞过一次（用超时造的），真工具卡死没验证
六  跨机器           只在一台 Windows 上跑过
七  导入导出的完整往返  验过合并逻辑，没验过「导出到另一台机器导入后能跑」
```
