# 使用方法 · 思维空间（父插件）

思维空间是**技能库**：把一串工具调用存成一条技能，之后一句话跑完整条链，不必让模型每步重新推理。

这份只讲父插件怎么用。画布见 [使用-思维画布.md](使用-思维画布.md)。

---

## 一、整体位置

```
WhaleLife 宿主
└── 插件页面 → 思维空间（父）        ← 技能库、设置、功能库、复合功能库
    └── 思维画布（子）              ← 画流程图、发布技能
```

| 页面 | 地址 | 干什么 |
|---|---|---|
| 设置 / 总览 | `/plugins/thinking-space/` | 开关、允许使用技能、导入导出 |
| 功能库 | `/plugins/thinking-space/space` | 单步技能列表，可跑一次、可编辑 |
| 编辑 | `/plugins/thinking-space/edit?id=` | 改步骤、参数、顺序 |
| 导出 | `/plugins/thinking-space/export` | 全部技能打成 JSON |
| 技能组（画布内） | 9281 →「技能组」标签 | 读同一份技能库，只读展示 |

## 二、三个入口，挑一个

### 1）让它自己跑（最常用）

```
space_skills()                        → 看有哪些技能
space_run({ id, params })             → 跑一条
```

一条技能的完整示例（搜资料并读首条）：

```json
{
  "schemaVersion": 1,
  "name": "搜资料",
  "kind": "composite",
  "description": "搜索并读取首条可读网页",
  "params": [
    { "name": "query", "label": "关键词", "type": "string", "required": true,
      "aliases": ["关键词", "q"] }
  ],
  "steps": [
    { "id": "n1", "tool": "surf_search", "plugin": "surf",
      "params": { "query": "${query}", "limit": 3 }, "next": "n2" },
    { "id": "n2", "tool": "surf_read", "plugin": "surf",
      "params": { "url": { "$try": [
        "${n1.data.results[0].url}",
        "${n1.data.results[1].url}",
        "${n1.data.results[2].url}"
      ] } }, "next": null }
  ]
}
```

跑：

```
space_run({ id: "搜资料", params: { query: "WhaleLife 插件规范" } })
```

回执是**逐步**的，每步带状态和输出；成功那一步的 `data` 就是下一步要接的东西。

### 2）从一串工具名生成草稿

不知道参数怎么接，先让它猜：

```
space_draft({ name: "每日巡检", tools: ["hands_list", "hands_read"] })
```

返回一条**没保存**的草稿，附预校验结果：归属插件、必填参数、`next` 链、
以及哪个字段接不下去。看完再 `space_skill_save` 落库。

### 3）让它自己整理（学会技能）

打开设置里的「自动整理」后，插件监听每次工具调用，凑够重复序列就存成技能：

```
按会话分组 → 按时间排序 → 间隔超窗口(默认120分钟)断开
→ 切 2~5 步 n-gram → 出现 ≥ 阈值(默认3) → 库里没同样序列 → 存成 auto-<hash>
```

**永远不进整理的**：`space_*`（自己）、`hands_*`（动手类）、transient 调用（只记名字）。

## 三、写技能的三条硬规则

```
① 占位用 ${...}，数组下标用方括号
   ✅ ${n1.data.results[0].url}
   ❌ ${n1.data.results.0.url}      ← 校验器会指出哪一步写错

② 参数名用工具 schema 的机器名，人看的名字放 label
   "name": "query"  ← 调工具时用这个
   "label": "关键词" ← 页面显示这个
   "aliases": ["关键词"] ← 收旧写法

③ {"$try": [...]} 是候选回落
   按顺序试，第一个成功就采用，每个候选的成败都进回执
```

**最容易踩的一条**：跨步骤只能引用**上游某一步的某个字段**，不能整段转发。
写 `"text": "${n1}"` 会被拦下，必须 `"text": "${n1.data.text}"`。

## 四、跑完怎么看回执

| 状态 | 含义 | 该怎么做 |
|---|---|---|
| `ok` | 正常 | — |
| `failed` | 这一步可重试 | 看 `error` |
| `uncertain` | 结果未知（单步超时） | **不要自动重试**，可能已经产生副作用 |
| `blocked` | 缺前置条件（技能不存在、缺必填参数、含未确认的副作用步骤） | 补条件 |
| `skipped` | 这步没成，后面不依赖它，已继续 | 看整体 |

全部步骤都是 `skipped` 时，整体抬成 `failed`——一步没成，报"跳过"会让人以为没事。

**含副作用步骤**（写文件、跑命令、发消息）跑之前要给 `confirmSideEffects: true`，
不给就是 `blocked`，不是失败。

## 五、图形化：画完再发布

画布上有「发布到思维空间」，把画出的流程转成上面那种技能定义。
两条路都通，改的是同一份 `data/skills.json`。

发布时如果带了跨步骤连线，要给**字段路径**（例如 `data.text`），否则宿主返回 422：

```
publish 422 {"ok":false,"error":"n2：占位须使用已声明参数或前序步骤字段，
例如 ${关键词} 或 ${n1.data.results[0].url}。"}
```

这条报错不是坏了，是"你没说是哪个字段"。填上就过。

## 六、常见失败

| 现象 | 原因 |
|---|---|
| 保存被 `blocked`，说某工具不存在 | 技能里用到的工具，宿主里得真的装着 |
| 带模型的步骤报「没有可用的对话模型」 | 缺 `models` 依赖，启宿主时没带 |
| 发布 422，说占位不合格 | 跨步骤没写字段路径，见上 |
| 「允许使用整理好的技能」关着 | 技能列得出来，`space_run` 会拒 |
| 画布端口标「未声明」 | 宿主没有 `catalog()`，降级用 `list()`，字段拿不到 |
