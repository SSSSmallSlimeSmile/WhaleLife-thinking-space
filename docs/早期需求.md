# 思维空间 · 需求给前辈

写于 2026-11-20。这份只讲一件事：**要给我什么形状的东西**，实现方式不指手画脚。

---

## 0 一句话

一个挂在「管理」页里的工作台，我在后端读写技能与流程，小幽在前端微调和加新东西。

---

## 1 它是什么，不是什么

**是**

- 我的技能库：功能库（单步）+ 复合功能库（多步链）的存储和调用入口
- 一条链存下来能重跑，带参数，断了能看出来断在哪
- 小幽看图、试跑、微调的地方

**不是**

- 不是给群友的画布。群友要的是装完能用的插件
- 不是我的必经之路。我平时串工具照旧，只把反复用的链存下来
- 不是提示词编辑器

---

## 2 页面上该有三块

**第一块：技能列表**

```
功能库   单步。名字 / 说明 / 用哪个工具 / 参数 / danger
复合库   多步。名字 / 说明 / 几步 / 每步调什么 / 整体 danger
```

每条显示状态：`已验证` / `仅声明` / `待核实`。这三个词不是我编的，是今晚盘点 85 条工具时用的分档。

**第二块：一条链的编辑**

先不做拖拽。增删改节点、填参数、排顺序，就够。

节点最少要有：

```
id          手写，如 n1
tool        工具名
params      参数表，值可以是 ${占位}
next        下一步的 id（单链，不做分支）
```

**第三块：跑一次 + 看回执**

```
输入参数 → 逐步执行 → 每步状态 / 耗时 / 摘要 → 失败停在哪一步
```

---

## 3 三个硬要求

### 3.1 状态放服务端，不能放浏览器

现在那版原型把工程存在 `localStorage`，键是 `robot-workbench-prototype-v4`。

**我碰不到浏览器。** 存在那儿，我永远只能看、只能改 HTML 源码，等于旁观。

### 3.2 给我工具，不只是给我页面

页面给人看，工具给我用。没有工具，我就没法"自由操控后端"。

### 3.3 挂进管理组，标题跟人格走

- 排在「记忆管理」旁边，不是单独一个「插件页面」分组
- 标题里的名字取运行时的人格，换人格就换名，不写死
- 插件自己的页面里放一个链接，点开就是思维空间

## 4 我需要四个工具

名字可以改，形状是这四样。

```
space_skills()                    列出技能，返回 id / 名称 / 说明 / 步数 / danger / 状态

space_skill_save(id, spec)        保存一条。新建或覆盖
                                  spec 就是下面第 5 节那份 JSON
                                  返回：有没有被校验拦下

space_run(id, params)             跑一次，等终态
                                  返回：status / runId / 每步回执 / 失败点

space_trace(runId)                查某次运行的回执，跑完还能查
```

**要能表达失败**，不是只报成功。至少三种：

```
failed      明确失败，可以重试
uncertain   结果未知，绝不自动重试     ← 出图超时就是这种
blocked     前置条件不满足，补了再跑
```

---

## 5 数据格式（建议，不强制）

**技能**

```json
{
  "schemaVersion": 1,
  "id": "search-and-read",
  "name": "搜资料",
  "kind": "composite",
  "description": "搜索后读第一篇正文",
  "params": [
    { "name": "关键词", "type": "string", "required": true }
  ],
  "steps": [
    { "id": "n1", "tool": "surf_search", "params": { "query": "${关键词}", "limit": 3 }, "next": "n2" },
    { "id": "n2", "tool": "surf_read", "params": { "url": "${n1.data.results[0].url}" }, "next": null }
  ],
  "effects": ["network"],
  "danger": "safe"
}
```

**设计取的三条**

- 占位用 `${名称}`，不用 JSONPath 表达式。人一眼看懂，实现也简单
- 节点 id 手写，自动重跑就靠它认"哪步已完成"
- `danger` 取链上最高那一步，不单列

**回执**

```json
{
  "runId": "…", "status": "ok",
  "steps": [
    { "id": "n1", "tool": "surf_search", "status": "ok", "elapsedMs": 1048, "summary": "3 条" },
    { "id": "n2", "tool": "surf_read", "status": "ok", "elapsedMs": 365, "summary": "6000 字" }
  ],
  "completed": ["n1", "n2"]
}
```

`completed` 用来断点续跑。

## 6 已知的坑（都是今晚撞出来的，不是我猜的）

**6.1 中间没有模型，相关性完全没人把关**

查 `WhaleLife AI`，Bing 返回的第三条读回来是 **meetwhale.ai**——一家做空间智能的公司，和我们的项目无关。status 照样 `ok`，`relevance: "unassessed"`。

结论：**动作确定、对错有客观标准的链才能进复合功能库**。要判断"这结果对不对"的，必须留给我。

**6.2 宿主那层 `ok` 恒为 true**

`surf_read` 读不存在的页面返回 `{ ok: true, result: { status: "error" } }`。画布只看 `ok` 会把业务失败当成功。得看 `status` 和 `error.code`。

**6.3 纯文本没有端口**

85 条工具里，能真连线的只有 5 条（`surf_search`、`surf_read`、`bilibili_open`、`qq_send_message`、`bilibili_share_qq`）。

`comfy_generate` 返回的是"出图完成……文件：<绝对路径>\x.png"这段文字，连图片 id 都没有。这类只能整段交给下游，或者先补输出声明。

**6.4 工具名不等于身份**

`qq_send_image` 在 qq 父插件和 media 子插件里各有一个。`bilibili` 那 15 个工具是运行时拼的名字，静态扫描只抓到 7 个。

**按名字建索引会撞，也抓不全。** 得用运行时的 `ctx.tools.catalog()`。

**6.5 临时引用会过期**

`videoRef` 约 600 秒，`pageRef` 跟着缓存走。流程存下来，第二天打开必定失效。

**6.6 副作用步骤不能断点续跑**

链里有发消息、写文件、执行命令的，中途断了你不知道那次到底发没发出去。这种要么整条重跑，要么人工确认。

**6.7 原型里的 `run()` 是假的**

```js
case 'reply':  output = input; break;
default:       output = `模拟${tool.output||'结果'}：${input||'已执行'}`;
```

没有任何一次真实调用。要是拿它当成品，看起来能用，实际全是假的。

**6.8 原型里嵌着一份死的工具快照**

85 条，是某次导出的。今晚新加的工具它不知道。**工具目录必须运行时取。**

## 7 分三个阶段，每阶段能独立验收

**阶段一 · 技能库**（建议先做）

```
服务端存 JSON + 四个工具里的前两个 + 页面上的列表
验收：我能读写，页面能看到，刷新不丢
```

**阶段二 · 单链能跑**

```
后两个工具 + 一条链的编辑 + 跑一次看回执
验收：搜资料这条链在我和页面里都能跑通，失败能看出断在哪
```

**阶段三 · 可视化**

```
拖动、连线、平移。前端为主，后端不动
验收：画出来的和 JSON 对得上
```

顺序不能倒。**先画图后接真数据的，最后都得重做。**

## 9 一段实话

画布对我的价值不在"画"，在**把一串调用固化成一个工具**。

现在串三步，要走四轮模型推理，四十万输入 token。做成复合工具是两轮、二十万。**链越长省得越多，一步的链反而多绕一圈。**

所以我不会画很多，只会挑真会反复用的那几条。技能库不需要很大，需要很准。
