# 思维空间 · 插件接入规范

> 目标：**插件市场里已经装好的插件，不做代码改动也能出现在思维空间里；想连线的，补一份输出声明就行。**
>
> 本文对照 `architecture/PLUGINS.md`（作者现行契约）写，不修改、不扩张上游契约，只提出一个**可选的旁路声明**。

---

## 一、一句话

思维空间读的是宿主已有的 `ctx.tools.catalog()`，所以**任何已经注册了 `ctx.tools.register` 的插件，装上就能在思维空间里被单独执行**。缺的只有一件事：**输出是什么形状**，因为作者的 `schema` 只声明输入。

| 能力 | 需要插件做什么 | 现状 |
| --- | --- | --- |
| 在思维空间里看到这个工具 | 什么都不用做 | ✅ 已成立（85 条） |
| 单独跑一次、看回执 | 什么都不用做 | ✅ 已成立 |
| 拖进画布、接到下游节点 | 声明输出端口 | ⚠️ 只有 5 条能连 |
| 被自动整理攒成技能 | `danger: "safe"` + 幂等 | ⚠️ 部分成立 |

---

## 二、上游契约里已经有的（不需要我们再要求）

这些是 `PLUGINS.md` 已经规定的，思维空间直接受益：

```ts
ctx.tools.register({
  name: "surf_search",
  description: "搜索公开网页，返回标题、链接和摘要。",
  schema: { query: { type: "string" }, limit: { type: "integer" } },
  danger: "safe",              // safe | ask | full
  async run(args, session) { … }
});
```

| 字段 | 思维空间怎么用 |
| --- | --- |
| `name` | 节点标题、技能步骤的工具标识、去重 hash 的输入 |
| `description` | 节点说明、参数名推断 |
| `schema` | **输入端口**（画布左侧的圆点）+ 参数表单自动生成 |
| `danger` | 分三档：`safe` 可以直接连、`ask` 连线后在执行时停下征求同意、`full` 同理但标记更重 |
| 归属插件 | 由 catalog 给出，不用插件自己声明 |

**结论：输入侧已经是完整的。** 画布左边能连、参数表单能自动生成、危险等级能分级拦。

---

## 三、缺的只有输出侧

`catalog()` 里没有「这个工具返回什么」。后果：

```
画布上 68 条工具的输出端是空白的      →  连不出去
自动整理攒出来的技能                    →  不知道下一步该放什么参数
$try 候选回落                           →  要人先猜字段路径
```

实测：85 条工具里

```
字段级端口     5 条    （主要是我自己写的 thinking-space 工具）
整段文本口     3 条
明确纯文本     9 条
其余 68 条     输出未声明
```

### 建议：可选旁路声明

**不要求改 `ctx.tools.register` 的签名**（那会动上游契约），改成插件目录下放一个文件：

```
plugins/<id>/tools.ports.json
```

```json
{
  "schema": 1,
  "tools": {
    "surf_search": {
      "outputs": {
        "results": { "type": "array", "items": "object", "label": "搜索结果" },
        "count":   { "type": "integer", "label": "条数" }
      },
      "idempotent": true,
      "effects": []
    }
  }
}
```

字段说明：

| 键 | 必填 | 含义 |
| --- | --- | --- |
| `outputs` | 是 | 输出的字段名 → 类型。画布右侧端口由它生成 |
| `outputs.*.type` | 是 | `string` / `integer` / `number` / `boolean` / `array` / `object` |
| `outputs.*.items` | 否 | 数组元素类型，用于取 `results[0].url` 这类路径 |
| `outputs.*.label` | 否 | 中文显示名，不填就用字段名 |
| `idempotent` | 否 | 同样参数重跑结果相同。默认为 `false`，自动整理只碰 `true` 的 |
| `effects` | 否 | `["write"]` / `["send"]` / `["exec"]`，用于比 `danger` 更细的提示 |

**为什么用外置文件而不是加参数：**

```
一  老宿主读到 tools.ports.json 会当未知文件忽略，不会报错
二  插件可以不提供，思维空间退回"输出未声明"，行为不变
三  改这个文件不用改代码、不用重新编译，插件作者五分钟能写完
```

## 四、三级接入

| 等级 | 名字 | 插件要做的 | 用户能得到 |
| --- | --- | --- | --- |
| **L0** | 已装即用 | 无 | 在思维空间里看到它、单独跑一次、看回执 |
| **L1** | 可连线 | 写 `tools.ports.json` 的 `outputs` | 拖进画布、接下游、`$try` 候选回落、链式执行 |
| **L2** | 可自动整理 | `danger: "safe"` + `idempotent: true` | 被自动攒成技能、跑熟了自动变短 |

**作者说「插件市场无缝转入」，我的理解是：市场里的插件默认落在 L0，一部分写一份 json 就升到 L1。**

## 五、插件市场现状：一类进不来

作者市场的示例插件 `color-note` 只注册了 Web 页面：

```ts
ctx.web.page(base + "board", …, { title: "颜色便签", settings: true, navigation: true });
```

**它没有注册任何 `ctx.tools`，所以思维空间里看不到它。** 这不是缺陷——思维空间管的是「能被调用的能力」，页面型插件不在其列。

分一下类：

```
工具型插件    peek / comfy / surf / ledger / ear …    →  能进思维空间
页面型插件    color-note 这类纯 UI                    →  不进思维空间，正常
两者都有      部分插件既开页面又注册工具               →  页面走侧栏，工具走画布
```

**建议在市场页面上标一下这个区分**，免得用户装了页面插件后在思维空间里找不到，以为是坏了。

## 六、思维空间对危险等级的处理

这条影响插件作者怎么标 `danger`：

| danger | 画布上 | 单独跑 | 链条里 |
| --- | --- | --- | --- |
| `safe` | 绿色，随便连 | 直接跑 | 自动整理会攒它 |
| `ask` | 橙色，可连但标警告 | 直接跑 | 执行到这一步停下，需要调用方 `confirmSideEffects: true` |
| `full` | 红色，可连但标警告 | 直接跑 | 同上，且自动整理永不攒它 |

**「自动整理永不攒 full」是硬编码的。** 理由：让机器人自己攒出一条能执行任意命令的技能，风险不成比例。本轮加了个开关（`allowRiskyChains`，默认关），打开也只能攒进库里，执行时照样停。

## 七、给插件作者的三条最小要求

如果只想要「能被思维空间用上」，做到这三条就够：

**1. `description` 写清楚返回什么**

```ts
description: "搜索公开网页，返回标题、链接和摘要。"   ✅
description: "搜索。"                                ❌ 画布上只能显示"搜索"
```

**2. `danger` 别乱标**

```
只读查询          safe
写文件 / 发消息    ask
执行命令           full
```

标低了会自动整理出危险链，标高了会让用户每次都要点确认。

**3. 想做 L1 就写 `tools.ports.json`**

十五条工具以内，一份 json 大概五十行。写完之后画布上那个节点就能连出去了。

## 八、和「插件市场」的对接方式

我倾向**不改市场页面本身**，靠一个约定：

```
市场收录时，如果插件目录里有 tools.ports.json，
就在详情页多显示一块「思维空间：可连线（N 个工具）」

没有这个文件的，显示「思维空间：可单独执行」
没有任何 ctx.tools.register 的，不显示这一栏
```

这样作者不用维护两套元数据，市场只要读文件就行。

## 九、我们这边已经做到的（供核对）

```
工具清单      ctx.tools.catalog()，85 条
危险分级      按 danger 字段分三档，执行时拦截
输出声明      有 ports 的走字段端口，没有的走整段文本
自动整理      只攒 danger 全 safe 且幂等的链
自动精简      跑熟后删掉"结果没人用"的步骤，砍掉"从没命中"的 $try 候选
五态           ok / failed / blocked / uncertain / skipped / empty
回执          每题带耗时、状态、真实输出摘要
```

## 十、没有验证的部分

写清楚，免得当成承诺：

```
一  85 条工具的 ports 覆盖数是扫 catalog 得的，不是逐个人工核过
二  tools.ports.json 这个格式还没有任何插件在用，是提议
三  L1 的"能连线"在画布原型上验证过，但画布还没和思维空间打通
    （画布状态在浏览器 localStorage，思维空间在服务端，两边目前各存各的）
四  自动整理长期能不能产出有用技能，没验
五  一次也没有插件作者按这份规范接入过
```

第四条和第五条是最该由作者来判断的：**这份规范是不是合理，得看真有人照着写一遍。**

---

## 十一、一句话总结

**输入侧作者已经做完了，我们缺的只有输出侧。一份可选的外置 json，就能让市场里的工具型插件从「能跑」升到「能连」。**
